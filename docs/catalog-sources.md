## Identity boundaries

- **RabbitMQ:** NVD deprecates the old `vmware / rabbitmq` identity in favor of `broadcom / rabbitmq_server`. The new entry follows the current identity. It does not silently match old product names or client libraries. [NVD deprecation record](https://nvd.nist.gov/products/cpe/detail/83bb7445-da7e-42d9-9def-0041509da83d).
- **Express:** the selected identity is `openjsf / express`. Older `expressjs / express` CPEs are separate identities and can require a separate asset. [NVD deprecation record](https://nvd.nist.gov/products/cpe/detail/341647).
- **Requests:** NVD's `python-requests / requests` entry explicitly redirects to `python / requests`; the catalog uses that target identity. The vendor name does not mean the entire Python runtime is affected.
- **pfSense:** CE and Plus are separate catalog entries. The CE entry follows `netgate / pfsense_ce`; earlier `pfsense / pfsense` and `netgate / pfsense` records are not implicitly aliased.
- **Pi-hole:** the entry watches Core. `ftldns` and `web_interface` use separate NVD product identities; Core alone does not cover every Pi-hole component.
- **Home Assistant, Jellyfin, Nextcloud, Jenkins and WordPress:** core product entries do not automatically include add-ons, integrations or plugins.
- **Log4j and Spring Framework:** review each affected component in the advisory. Log4j is not a promise that every Java logging library is watched; Spring Framework is separate from Spring Boot and Spring Security.
- **UniFi Network, Proxmox Backup Server and Vaultwarden:** these entries do not imply coverage of every UniFi device, Proxmox VE or the official Bitwarden server respectively.

No new vendor-agnostic identities were added. Each new entry restricts matching to its reviewed vendor/product pair. This reduces ambiguous matches but can miss CVEs published under alternate identities; use deliberate additional assets for those identities rather than assuming fuzzy matching. The original vendor-agnostic entries retain their documented behavior for backward compatibility.

Maintainers should verify both the product and vendor before adding an entry, document renames explicitly, include meaningful exclusions in the description and keep stable catalog IDs. Automated tests validate unique IDs/identities, pack references, preview/import deduplication and conservative matching with representative reviewed CPEs. CI deliberately does not fetch live NVD data.
