# Development agent runner

`scripts/agent-runner.sh` runs one bounded `codex exec` session in the project workspace. It refuses a dirty working tree or overlapping run, gives the agent a 30-minute deadline, and writes a private log to `data/agent-runner/`. The prompt limits work to one increment and prohibits publishing, external messages, changes to the runner or unrelated projects, and further automation. The workspace-write sandbox is not a substitute for reviewing agent changes. A failed or interrupted run may leave uncommitted changes; later runs stop until those are reviewed. The agent may be unable to commit if its sandbox protects Git metadata.

The runner needs a working Codex CLI login and network access on the host. Model usage may consume account allowance or incur costs depending on account and configuration. It does not start itself or guarantee that the computer remains online. Inspect `data/agent-runner/` and `git status` after each run. Never put tokens into prompts or logs. Logs may contain project information; manage retention locally.

The `deploy/systemd` files are examples for a Linux user service, with example paths set to ~/projects/vulnrelay; adjust them to your checkout. They are not installed or enabled. After reviewing account usage, sandbox configuration and paths, install them under `~/.config/systemd/user/`, run `systemctl --user daemon-reload` and `systemctl --user enable --now vulnrelay-agent.timer`. Check `systemctl --user list-timers` and `journalctl --user -u vulnrelay-agent.service`. Stop future runs with `systemctl --user disable --now vulnrelay-agent.timer`; stop a currently running job separately with `systemctl --user stop vulnrelay-agent.service`. Timer persistence depends on the host and user systemd manager remaining available. This is a development runner, not the product's CVE monitoring scheduler.
